# Chống DoS cho GraphQL: giới hạn depth, complexity và timeout

**Lĩnh vực:** Cyber security (OWASP / API hardening)

## What it is
GraphQL cho client tự chọn hình dạng query, nên một request nhỏ có thể tạo ra lượng việc khổng lồ (nested sâu, danh sách lớn, nhiều alias). OWASP GraphQL Cheat Sheet ghi rõ: depth và amount mặc định có thể không bị giới hạn nên dẫn tới DoS, và GraphQL không hỗ trợ sẵn việc này mà cần cài thêm.
Ba lớp phòng thủ chính: **depth limit**, **query complexity (cost)** kèm **pagination/amount limit**, và **timeout**.

## Why it matters
- Schema có quan hệ hai chiều (`album -> songs -> album -> ...`) cho phép viết query lồng sâu N tầng, mỗi tầng nhân số lượt gọi DB (OWASP có đúng ví dụ này).
- Rate limit theo request không đủ: 1 request có thể = 1000 resolver call.
- Với NestJS + federation, gateway/subgraph đều là nơi tính toán đắt; DataLoader giảm N+1 nhưng không chặn được query quá lớn.

## Ví dụ (NestJS, code-first, Apollo)
Cài `npm i graphql-query-complexity`. Plugin dưới đây lấy từ tài liệu NestJS (chương Complexity):

```typescript
import { GraphQLSchemaHost } from '@nestjs/graphql';
import { Plugin } from '@nestjs/apollo';
import { ApolloServerPlugin, BaseContext, GraphQLRequestListener } from '@apollo/server';
import { GraphQLError } from 'graphql';
import { fieldExtensionsEstimator, getComplexity, simpleEstimator } from 'graphql-query-complexity';

@Plugin()
export class ComplexityPlugin implements ApolloServerPlugin {
  constructor(private gqlSchemaHost: GraphQLSchemaHost) {}

  async requestDidStart(): Promise<GraphQLRequestListener<BaseContext>> {
    const maxComplexity = 20;
    const { schema } = this.gqlSchemaHost;
    return {
      async didResolveOperation({ request, document }) {
        const complexity = getComplexity({
          schema,
          operationName: request.operationName,
          query: document,
          variables: request.variables,
          estimators: [fieldExtensionsEstimator(), simpleEstimator({ defaultComplexity: 1 })],
        });
        if (complexity > maxComplexity) {
          throw new GraphQLError(`Query is too complex: ${complexity}. Max: ${maxComplexity}`);
        }
      },
    };
  }
}
```

Khai báo `ComplexityPlugin` trong `providers` của module. Đặt cost cho field đắt:

```typescript
@Field({ complexity: 3 })
title: string;
```

Depth limit: OWASP gợi ý `graphql-depth-limit` cho JavaScript (hoặc `MaxQueryDepthInstrumentation` cho graphql-java, hữu ích nếu service Spring Boot của bạn dùng graphql-java). Timeout: OWASP khuyến nghị đặt ở cả application và infrastructure (reverse proxy), vì timeout đơn thuần có thể kích hoạt quá muộn khi query đã ngốn tài nguyên.

## Trade-offs / khi nào KHÔNG cần
- Complexity là ước lượng: số `maxComplexity` phải tinh chỉnh theo query thật của frontend, đặt thấp quá sẽ làm hỏng UI hợp lệ (dashboard nhiều widget).
- Danh sách cần nhân cost theo `first/limit`: estimator mặc định chỉ đếm field, bạn phải tự viết estimator nếu muốn tính theo kích thước page.
- Timeout không thay thế limit tĩnh (OWASP nói rõ nó có thể không đủ hiệu quả).
- Persisted queries (allowlist) mạnh hơn nhiều với API chỉ phục vụ app của bạn; nhưng không dùng được cho API public tự do.
- Với federation: áp ở gateway/router cho traffic ngoài; subgraph không nên mở ra internet, nếu không limit ở gateway bị bỏ qua.

## Thử trong 15 phút
1. Trong một NestJS service có GraphQL: `npm i graphql-query-complexity`, thêm `ComplexityPlugin` ở trên, đặt `maxComplexity = 20`.
2. Viết query lồng 3-4 tầng quan hệ (vd. `user { posts { author { posts { id } } } }`) và gọi bằng Altair/curl, xác nhận nhận lỗi "Query is too complex".
3. Gắn `@Field({ complexity: 5 })` vào field đắt, quan sát số complexity đổi (log bằng `console.log`).
4. Bonus: kiểm tra proxy (nginx/Traefik trong Compose) có `proxy_read_timeout` hợp lý làm lớp timeout thứ hai.
